# MVP v0.1

> この文書は小規模に動かして検証する初期MVPの範囲を定める。Phase 1全体の正式な12訓練と出題方針は [`LEARN_CURRICULUM.md`](LEARN_CURRICULUM.md) を参照する。以下の4テーマとMVP完成条件は、正式カリキュラム全体の修了条件ではない。

## 1. 目的

最初のバージョンでは、完成版の機能を大量に作ることを目的としない。

本作品の中心となる、

**Learn → Build → Attack & Defend**

の3フェーズを、小規模でも実際に遊べる状態にすることを目的とする。

---

## 2. Phase 1 - Learn

MVPでは、正式カリキュラムの一部として以下の4テーマのみ先に扱う。

### Stage 1：コンピュータとネットワーク

学習内容：

* クライアント
* サーバー
* IPアドレス
* ポート

### Stage 2：Webの基本

学習内容：

* Webページ
* HTTP
* Webサーバー
* データベースの役割

### Stage 3：Python基礎

学習内容：

* 変数
* if
* for

### Stage 4：セキュリティ基礎

学習内容：

* パスワード
* 認証
* ログ
* 不要なサービスを公開するリスク

各ステージは、

1. 短い説明
2. 簡単な問題またはミッション
3. 正解・不正解のフィードバック

という流れを基本とする。

最初のバージョンでは、自由入力型の高度なコード実行環境は必須としない。

---

## 3. Phase 2 - Build

プレイヤーが簡単な仮想システムを完成させる。

初期状態：

* Internet
* Web Server
* Database
* User

を基本要素とする。

プレイヤーは学習内容を参考にしながら、画面上で必要な要素や設定を選択し、自分のシステムを完成させる。

MVPでは本物のサーバー環境を構築する必要はなく、ゲーム内のシミュレーションとして実装してよい。

システムの状態は保存できるようにする。

---

## 4. Phase 3 - Attack & Defend

MVPではDefense 1ミッション、Attack 1ミッションのみ実装する。

### Defense Mission 1

自分のシステムに不審なログイン試行が発生する。

プレイヤーは、

* ログを見る
* 異常を発見する
* 複数の対応策から適切なものを選ぶ
* 結果と理由を確認する

という流れで防御する。

### Attack Mission 1

ゲーム内に用意された完全な仮想敵システムを調査する。

プレイヤーは、

* システム情報を見る
* 公開されているサービスや設定を確認する
* セキュリティ上の弱点を推測する
* 適切な選択肢を選ぶ
* 仮想システム内の目標を達成する

という流れを体験する。

MVPでは実在する外部システムへの通信、スキャン、攻撃は一切行わない。

攻撃処理はゲーム内部のシミュレーションとして実装する。

## 6. MVPで実装しないもの

以下はv0.1では実装しない。

* 本格的なCTF
* Dockerによる脆弱環境
* 外部ネットワークへの通信・スキャン
* 高度なPythonコード実行環境
* 本格的なLinux端末
* 複数の敵勢力
* PvP
* オンラインマルチプレイ
* ランキング
* 大量のステージ
* 高度なAI敵
* 本格的なペネトレーションテスト環境
* 複雑な経済・資源管理
* 完成版のサバイバルシステム

これらはMVP完成後、実際に遊びながら必要なものを判断して追加する。

---

## 7. MVP完成条件

以下をすべて満たした時点でMVP v0.1完成とする。

* アプリが正常に起動する
* タイトル画面からゲームを開始できる
* Phase 1の4ステージを遊べる
* Phase 2で簡単な仮想システムを構築できる
* Defense Mission 1を遊べる
* Attack Mission 1を遊べる
* ゲーム進捗を保存できる
* 最初から最後まで重大なエラーなく進行できる
* 基本的な自動テストが成功する

---

## 8. v0.1以降

MVP完成後は仕様書を先に固定せず、実際にプレイして感じた問題点や新しいアイデアをもとに、バイブコーディングで機能を追加・改善する。

将来的な候補：

* Linux学習
* Python学習の拡充
* SQL
* HTTPの詳細
* ログ解析
* ネットワーク構築
* セキュアコーディング
* 脆弱性学習
* Blue Teamミッション追加
* Red Teamミッション追加
* CTF
* Dockerを利用した安全な演習環境
* サバイバル・ストラテジー要素の強化
