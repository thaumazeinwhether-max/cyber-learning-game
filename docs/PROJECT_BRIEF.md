# Cyber Learning Game - Project Brief

## 1. プロジェクト概要

本プロジェクトは、IT・プログラミング未経験者がゲームを楽しみながら、IT、Python、システム開発、サイバーセキュリティの基礎を段階的に身につけることを目的とする学習ゲームである。

学習した知識を単なるクイズで終わらせず、

**Learn → Build → Attack & Defend**

の3フェーズを通して、知識を実際に使う体験につなげる。

本作品はバイブコーディングによって開発する。
最初から完成形を固定せず、小さく動くものを作り、実際に遊びながら機能・ゲーム性・UIを段階的に改善していく。

---

## 2. Phase 1 - Learn

IT、Python、Web制作・開発、データベース、セキュリティ、監視・インシデント対応の基礎をゲーム形式で学ぶフェーズ。Phase 2以降に必要な基本的な新規学習を、ここでほぼ完了させる。

正式な12訓練の順序・範囲・出題方針は [`LEARN_CURRICULUM.md`](LEARN_CURRICULUM.md) を参照する。以下は企画初期に挙げた学習候補であり、正式な範囲は同文書を優先する。

企画初期の学習候補：

* コンピュータの基本
* OSの基本
* ファイルとディレクトリ
* ネットワークの基本
* IPアドレス
* TCP / UDP
* ポート
* DNS
* HTTP / HTTPS
* クライアントとサーバー
* Webの基本
* データベースの基本
* Linuxの基本
* Pythonの基本

  * 変数
  * 条件分岐
  * 繰り返し
  * リスト
  * 辞書
  * 関数
  * ファイル処理
* セキュリティの基本

単なる説明と確認問題だけではなく、ゲーム内のミッションを解決するために知識を使う形式を目指す。

---

## 3. Phase 2 - Build

Phase 1で学んだ知識を利用して、自分の仮想システムやWebページを構築するフェーズ。

プレイヤーは小さなシステムから開始し、ゲームを進めながら機能を増やしていく。

例：

* Webページ
* Webサーバー
* アプリケーション
* データベース
* ユーザー登録
* ログイン
* 権限管理
* ログ
* Firewall
* バックアップ
* その他のネットワーク・セキュリティ機能

このフェーズでは「守る対象がどのように作られているのか」を理解することを重視する。

---

## 4. Phase 3 - Attack & Defend

自分の仮想システムと仮想敵のシステムを使って、サイバーセキュリティの攻防を実践形式で学ぶフェーズ。

### Defense

仮想の敵が自分のシステムに攻撃を仕掛けてくる。

プレイヤーは、

* ログの確認
* 異常の発見
* ネットワーク構成の確認
* アクセス権の確認
* セキュリティ設定の改善
* インシデント対応
* 復旧

などを通してシステムを守る。

### Attack

ゲーム内またはローカルの演習専用環境として用意された仮想敵システムを調査する。

プレイヤーは、

* システムの構造を理解する
* 情報を集める
* セキュリティ上の問題を発見する
* 問題の原因を理解する
* 仮想環境内で目的を達成する
* 防御・改善方法を学ぶ

という流れを体験する。

ゲーム性として、若干のサバイバル・ストラテジー要素を取り入れる。

---

## 5. 学習方針

新しい知識は可能な限り、

1. Learn：基礎を学ぶ
2. Build：自分で使ってみる
3. Attack & Defend：攻防の中で応用する

という順番で登場させる。

プレイヤーが「なぜこの知識を学ぶ必要があるのか」をゲームを通じて理解できる設計を重視する。

---

## 6. セキュリティ上の原則

本作品はサイバーセキュリティ教育を目的とする。

攻撃・侵入に関する演習対象は、

* ゲーム内の仮想システム
* ローカル環境
* 明示的に演習用として用意された環境

のみに限定する。

実在する第三者のWebサイト、サーバー、IPアドレス、ネットワークなどへの無許可の攻撃・侵入・スキャンを目的とする機能は実装しない。

攻撃側の知識を扱う場合も、原理の理解だけでなく、防御方法・修正方法・安全な運用について学べる構成を重視する。

---

## 7. 開発方針

* バイブコーディングによって段階的に開発する
* 最初から全機能を完成させようとしない
* 小さく動く状態を維持する
* 実際に遊びながら仕様を改善する
* 初心者でも後から理解しやすいコードを重視する
* 不要に複雑な技術や設計を採用しない
* ゲームとしての楽しさと学習価値の両立を目指す

---

## 8. 初期MVP方針

最初のバージョンでは、3フェーズすべてを小規模に体験できることを目標とする。

詳細なステージ数、問題数、ゲームシステム、UI、技術構成については、開発を進めながら決定する。

完成形を最初から固定せず、バイブコーディングによる試行錯誤を重視する。
